Clicking a button sends a transaction to the Event API → Kafka → Processor → Postgres. The new balance comes back over Server-Sent Events from Postgres NOTIFY. Rejected events (e.g. overdrafts) never change the balance; see them with make dlq. Withdrawals then settle through a Temporal workflow: try an amount ending in .13 to watch the mock provider decline it and the workflow refund it automatically.
